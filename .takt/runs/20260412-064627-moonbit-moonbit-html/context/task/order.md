# タスク指示書

## 目的

`moonbit/` 配下にある生成済み MoonBit 実装をブラウザで起動できるようにし、ブラウザ起動用の HTML を用意する。  
そのうえで `playwright-cli` を使って実画面を確認しながら、UI をシャドウバース風のカードバトル UI に寄せて洗練させる。

## 参照資料

- `moonbit/`

`plan` エージェントは最初に `moonbit/` 配下を列挙し、MoonBit ソース、ビルド設定、生成済み JS/WASM、既存 HTML/CSS/JS、テストの有無を確認すること。

## 作業対象と優先度

### 高: `moonbit/` 配下の MoonBit 実装・ビルド設定

- `moonbit/` 配下の構成を調査し、ブラウザで実行するために必要なビルド手順・生成物・エントリポイントを特定する。
- MoonBit からブラウザで読み込める JS/WASM 等の成果物を生成する必要がある場合は、既存設定に沿ってビルドできるようにする。
- 既存のビルドコマンド、設定ファイル、出力先がある場合はそれを優先して利用する。
- ブラウザ起動に必要な最小限の配線が不足している場合は、`moonbit/` 配下に追加する。

### 高: ブラウザ起動用 HTML / JS / CSS

- `moonbit/` 配下、または既存構成上もっとも自然な場所に、ブラウザ起動用の HTML を用意する。
- HTML から MoonBit の生成物を読み込み、画面を表示できるようにする。
- 必要に応じて、ブラウザ起動用の JS と CSS を追加・変更する。
- 起動手順が静的サーバーを必要とする場合は、ローカルで起動できるコマンドを明確にする。

### 高: UI 表示・カードバトル画面

- 表示される UI をシャドウバース風のカードバトル UI に寄せて調整する。
- カード、盤面、手札、ステータス、操作ボタンなど、現在の実装で表示可能な主要要素を視認しやすく整える。
- `playwright-cli` で実際のブラウザ画面を確認し、スクリーンショットを見ながら複数回調整する。
- 空白画面、要素の画面外はみ出し、クリック不能な操作要素、著しく読みにくい文字を解消する。

### 中: Playwright による確認・スクリーンショット

- `playwright-cli` でローカル画面を開いて確認する。
- デスクトップ表示でスクリーンショットを取得する。
- 可能であればモバイル幅でも表示確認し、主要要素が破綻していないことを確認する。
- 最終報告に確認した URL、使用したコマンド、スクリーンショット取得結果を含める。

### 中: テスト

- 既存テストがある場合は、対象テストを確認して実行する。
- ブラウザ起動用 HTML/JS/CSS の追加に対して、既存のテスト基盤で検証可能な範囲のテストを追加する。
- Playwright テストの基盤が既にある場合は、ブラウザ表示が空白でないこと、主要 UI 要素が存在することを検証するテストを追加する。
- Playwright テスト基盤がない場合は、既存構成に合わせて最小限の検証方法を選ぶ。

### 低: 実行手順ドキュメント

- ブラウザで起動するためのコマンドと URL を、既存 README または `moonbit/` 配下の適切なドキュメントに追記する。
- MoonBit のビルドが必要な場合は、ビルドからブラウザ確認までの手順を記載する。

## 要件

1. `moonbit/` 配下の生成済み MoonBit 実装をブラウザで起動できる状態にする。
2. ブラウザ起動用の HTML を用意する。
3. HTML から MoonBit の生成物または既存の表示ロジックを正しく読み込む。
4. ローカルで画面を開ける起動コマンドとアクセス URL を明確にする。
5. `playwright-cli` を使って実画面を確認しながら UI を調整する。
6. UI はシャドウバース風のカードバトル UI に寄せる。
7. 実装後、ビルド・テスト・ブラウザ表示確認を実行する。

## plan エージェントへの指示

- `moonbit/` を参照資料として最初に読み込む。
- MoonBit のビルド設定、生成物、エントリポイント、ブラウザ実行可否をコードと設定から確認する。
- 既存の HTML/JS/CSS がある場合は、その構造を確認して変更対象を特定する。
- 既存の UI 表示ロジックが MoonBit 側にあるのか、生成 JS 側にあるのか、HTML/CSS 側にあるのかを切り分ける。
- ブラウザ起動までに必要なファイル追加・変更を、対象ファイルごとに計画する。
- `playwright-cli` で確認する具体的な起動手順、URL、確認観点を計画に含める。
- テスト追加が必要な場合は、既存テスト構成に沿って対象ファイルと検証内容を指定する。

## write_tests エージェントへの指示

- 計画に従い、プロダクションコード変更前にテストを追加する。
- 既存テスト基盤がある場合は、その命名・配置・実行方法に従う。
- 最低限、以下を検証するテストを作成する。
  - ブラウザ起動用 HTML または起動エントリが存在する。
  - UI 初期表示に必要な主要コンテナが存在する。
  - MoonBit 生成物を読み込むための参照が HTML/JS に存在する。
- Playwright テスト基盤が既にある場合は、画面が空白でないこと、主要 UI 要素が表示されることを検証する。
- 実装前のため失敗は許容されるが、import パスミスやテスト自体の構文エラーは修正する。

## implement エージェントへの指示

- 計画とテストに従い、ブラウザ起動用 HTML/JS/CSS と必要な MoonBit ビルド配線を実装する。
- UI をシャドウバース風のカードバトル画面として見えるように調整する。
- `playwright-cli` で実画面を開き、スクリーンショットを確認しながら必要な修正を行う。
- 実装後に以下を必ず実行する。
  - MoonBit のビルドまたは既存ビルドコマンド
  - 既存テストおよび追加テスト
  - ローカルブラウザ起動確認
  - `playwright-cli` によるスクリーンショット取得
- 最終出力に以下を含める。
  - 作成・変更したファイル
  - ブラウザ起動コマンド
  - アクセス URL
  - ビルド結果
  - テスト結果
  - Playwright 確認結果

## 再現手順・確認方法

1. `moonbit/` 配下で必要なビルドコマンドを実行する。
2. ブラウザ起動用 HTML を配信するローカルサーバーを起動する。
3. 指定 URL にアクセスして画面が表示されることを確認する。
4. `playwright-cli` で同じ URL を開く。
5. スクリーンショットを取得する。
6. 以下を確認する。
   - 空白画面ではない。
   - カードバトル UI として主要要素が表示されている。
   - 主要要素が画面内に収まっている。
   - ボタンや操作要素が視認できる。
   - 文字や数値が読める。
7. テストを実行し、追加・既存テストがパスすることを確認する。

## Open Questions

- `moonbit/` 配下の MoonBit 実装がブラウザ向けにどの形式でビルドされるかは、実際の設定ファイルと生成物を確認して確定すること。
